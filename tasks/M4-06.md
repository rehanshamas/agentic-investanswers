## Plan
What I found:
- `docs/plan.md` takes scope from the brief, "M1 to M4 and the four checks", but no file in the repo lists the four. From the weekly gates I read them as:
  1. **bar parity**, M1;
  2. **freshness**, M2;
  3. **indicator and backtest parity**, M3;
  4. **agents read through MCP, within plan checks and without internals**, M4.
  This needs Sham's confirmation.
- Three of the four have a command already:
  - `pnpm parity` (exits 0 only on exact build parity) and `pnpm rebuild-check` (0 only when nothing differs);
  - `pnpm freshness` (0 only when every step passes);
  - the leak test (M3-08).
- Nothing yet checks agents end to end against a running environment. `pnpm parity:indicators` (M3-03) does not exist; it waits on OI-30.

Steps:
1. **`pnpm acceptance [--url <platform>] [--skip-local]`** (`scripts/acceptance.mjs`, beside `owner-inputs.mjs`). It runs each check as its own command, records the exit code, how long it took and the summary lines, and turns that into **pass**, **fail**, **pending** (the check's command does not exist yet, with the owner input it waits on) or **not run** (a missing setting, for example no agent key). The four checks:
   - **Bar parity:** `pnpm parity --build` and `pnpm rebuild-check`.
   - **Freshness:** `pnpm freshness --url <url> --minutes 3` (needs `AIA_FRESHNESS_KEY`).
   - **Indicator and backtest parity:** `pnpm parity:indicators` once M3-03 adds it; until then "pending: OI-30, M3-03".
   - **Agents:** a new `pnpm agent-check` (step 2) against `--url`, plus the leak test.
   - **Also reported, not one of the four:** `pnpm check` and `pnpm e2e`. They can be skipped with `--skip-local` when only an environment is checked.
2. **`pnpm agent-check --url <platform>`** (`apps/platform/src/agent-check.ts`), with an agent key (`AIA_AGENT_KEY`), over MCP like a real agent:
   - `list_instruments`, `get_plan`, `get_bars` (bars come back) and `list_indicators`;
   - `get_indicator_output` for the first indicator listed;
   - a refusal for something outside the key's plan (with `upgradeUrl`);
   - a write attempt refused as read-only;
   - the request shows up in `GET /usage` for that key.
   Exit 0 only when all hold. Its pure parts get Vitest tests; the command runs against the e2e server in a test.
3. **The report:** `reports/acceptance/<date>-<env>.md` and `.json` (git-ignored):
   - the environment, git commit, time;
   - per check: result, evidence and how to rerun it;
   - the overall result, the open owner inputs that hold a check at pending, and a short "for the client" summary at the top.
   Exit 0 only when all four pass.
4. **`docs/demo-script.md`:** the client review, step by step, on staging (or dev until staging exists):
   - sign in;
   - BTC chart with live bars, scroll back two years;
   - the SMA from the settings dialog;
   - the freshness badge;
   - an agent through MCP;
   - `GET /usage`;
   - then `pnpm acceptance` and the report.
   Each step says what to show and what it proves.
5. **Docs:** architecture "Acceptance"; CLAUDE.md commands (`pnpm acceptance`, `pnpm agent-check`); card handoff.
