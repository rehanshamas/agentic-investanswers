# M3-01 IndicatorDefinition interface: declared inputs, output types (lines, bands, markers, levels), incremental update

## Goal
One shape every indicator takes: declared inputs (with limits), declared outputs (lines, bands, markers, levels), and a one-bar-at-a-time update, so the engine, the settings dialog and the parity harness all build on it, and ATR later is one new indicator (decision F-02).

## Plan
Approved by Sham on 2026-11-12 (project thread "Build side backlog tasks in parallel").

All in `contexts/indicators/src/domain` (pure, imports only `@aia/shared-kernel`):
1. `inputs.ts`: input kinds int, float, bool, choice, source (open, high, low, close, hl2, hlc3, ohlc4). Number inputs carry default, min, max, step. `defaultSettings`, `priceFromSource`.
2. `outputs.ts`: output kinds line, band, marker, level; `toDrawn` keeps only declared outputs and rounds to the instrument's price precision (CLAUDE.md rule 5).
3. `indicator-definition.ts`: `IndicatorDefinition<S>` with `id`, `version`, `name`, `inputs`, `outputs`, `init(settings)` and `step(state, bar, settings) -> { state, outputs }`, where `step` must not change the state it is given. `assertValidDefinition` for start-up checks.
4. `stepping.ts`: `startRun`, `commit` (closed bar, keeps state), `preview` (forming bar, keeps nothing), `runAll`. Shared by the engine (M3-04) and the parity harness (M3-03), so incremental and full runs cannot disagree.
5. Tests with a fake indicator in `src/test-support/` that uses every input and output kind; it is a test fake, not indicator source.

## Handoff
**Done.** Interface, drawn-output rounding, stepping rules and tests (46), all in `contexts/indicators`. `pnpm check` green.

**Surprises.** Float rounding at half ticks: `toFixed` and plain `Math.round(value * 100) / 100` both round values like 1.005 down (the product is 100.49999999999999). `toDrawn` cuts the product to 15 significant digits first, then rounds ties up (review on #85). TradingView's own half-tick behaviour must be confirmed against the SMA exports in M3-03.

**Left for later tasks.**
- M3-02: validate user settings against the declared limits server-side; describe the dialog fields from `inputs`. Settings do not yet get validated anywhere.
- M3-04: the engine caches by indicator id + version + instrument + timeframe + settings, stores `IndicatorRun` state after the last closed bar, and uses `preview` for the forming bar.
- Every output is rounded to the instrument's price precision. An output not in price units (an oscillator, a ratio) would need an optional per-output `precision`, like Pine's `precision=`; add it when an indicator needs it.
- Marker labels are cut to 16 characters; M3-08's leak test should cover them too.
- No colour or line-style inputs yet: styling is a chart concern, added with the chart wiring (M3-05) if needed.
