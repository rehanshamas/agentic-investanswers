## Goal
Stream BTCUSD and ETHUSD trades live, keep the forming 1-minute bar in memory, write each closed 1-minute bar to the raw store as soon as its minute ends, reconnect with backoff, and record a gap for every disconnect.

## Plan

**Finding before planning (2026-11-10).** `ws.coinapi.io` fails the TLS handshake from this machine (curl exit 35), the same reset M1-04 hit on `rest.coinapi.io`. CoinAPI's free plan also bills per message: a BTC trades stream runs to hundreds of thousands of messages a day, which would use up the $25 credit in days. Coinbase Exchange's public feed (`wss://ws-feed.exchange.coinbase.com`, `matches` channel, no key, free) is reachable. It is the same venue as the history backfill and the TradingView exports. **Recommendation: build the live stream on Coinbase, behind a `LiveTradesPort`, so CoinAPI can be added later as a second adapter.** This changes a provider named in the architecture, so Sham decides.

**Domain (pure, `contexts/hydration/src/domain/`)**
1. `forming-bar.ts`: fold trades into the forming 1m bar by **exchange trade time** (not the local clock). `close(nowSeconds)` returns the bar once its minute has ended plus a grace period (default 2 s, for messages that arrive late). A trade for an already closed minute is dropped and counted, never written, because raw is write-once. A minute with no trades gives no bar (bar-rules: missing minute). Prices and sizes go through the existing scaled-integer helpers, so no float reaches a bar.
2. `live-gap.ts`: a disconnect window `{ symbol, from, until }` in whole minutes. The minute in progress at the drop and every minute up to the first full minute after reconnect count as gap, and that forming bar is discarded rather than written half-built.

**Raw storage (hydration's own port; no cross-context contract changes)**
3. Live minutes are written as **one write-once object per closed minute**, beside the day: `raw/coinbase/<SYM>/YYYY/MM/DD.live/HHMM.parquet` (conditional put, as for days). Disconnect windows go in write-once `DD.live-gaps/<from>-<until>.json`.
4. `getDay` keeps its meaning: the backfilled day file plus its fills. A new `getLiveMinutes(ref)` returns the live minutes not covered by a day file. **Once the backfilled day file exists, it wins.** Live minutes are a stand-in for today and are superseded, never edited. `RawMinuteSource` (apps) reads the day file if present, otherwise the live minutes, so cooked stays rebuildable from raw alone.

**Application (`contexts/hydration/src/application/live-stream.ts`)**
5. `LiveStream` use case: subscribe → fold trades → on close, `putLiveMinute` → emit `MinuteClosed` to a callback. Reconnect with exponential backoff (1 s doubling to 60 s, with jitter, reset after 5 min of healthy stream) and heartbeat detection (no message for 30 s means dead). Every reconnect writes a live-gap record. The clock is injected.

**Adapter**
6. `adapters/coinbase/coinbase-trades.ts` implements `LiveTradesPort` with Node 22's built-in `WebSocket`, so **no new dependency**. A recorder that saves the raw messages it receives to a JSONL file, for replay.

**App wiring (`apps/hydration/src/live.ts`, `pnpm live [--symbol]`)**
7. Wire the stream to the S3 raw store, then on each `MinuteClosed` call market-data's `CookIntraday.applyNewMinutesToAll`. The live process reads today's minutes from an in-memory overlay rather than re-listing S3 every minute. One status line per minute (bars written, trades dropped late, reconnects).

**Tests / done-check**
8. *Replay test:* record about 30 min of real `matches` messages for BTCUSD with `pnpm live --record`, then replay them through `LiveStream` into an in-memory store. The bars must equal Coinbase's REST 1m candles for the same minutes: OHLC exact, volume exact. If REST's volume turns out to lag trades (M1-04 saw volume differ between sources), I will stop and report rather than loosen the check. **The recording lives in `contexts/hydration/test-data/`, not `fixtures/`** (`fixtures/` is protected and reserved for parity exports). If Sham wants it under `fixtures/`, that needs `AIA_ALLOW_FIXTURES=1` and the label.
9. *Reconnect test:* a fake port drops mid-minute. Check the backoff timings, that the half-built bar is not written, that a gap record covers exactly the lost minutes, and that bars resume after reconnect.
10. Unit tests for `forming-bar` (boundaries, late trade, grace, empty minute) and for the store's write-once on live minutes. Then `pnpm check`, `pnpm parity` and `pnpm rebuild-check`, because bars are touched.

**Out of scope:** repairing disconnect gaps from REST right away (M1-09's `pnpm gaps` repairs them once the day is backfilled), the latency probe (M1-11), Redis/BarClosed fan-out to browsers (M2-02/M2-04), stocks live (M1-07b), and deploying `apps/hydration` as a service.
