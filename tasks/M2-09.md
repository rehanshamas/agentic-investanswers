## Plan
Standing approval from Sham (2026-11-13); plan posted in the project thread.

1. `contexts/access` domain `plans.ts`: plan book (plans with included instruments and timeframes, default plan, email assignments, upgrade URL), strict parsing with named errors, `planIncludes`, `planFor`.
2. `PlanPolicy` behind `AccessPolicyPort`; the port gains `entitlements(principal)` (plan, what it includes, upgrade URL). Humans by their account's email; agents on the default plan until M4-01.
3. `config/plans.json` (Free: BTCUSD and ETHUSD, 1h and up; Pro: all), loaded at start-up (`AIA_PLANS` overrides). `accessFromEnv` uses it outside dev mode.
4. Platform: `403 forbidden` on `/bars` carries `upgradeUrl`; `GET /plan` returns the caller's entitlements.
5. Tests: domain parsing, policy, file loading, and a server matrix (each plan × `/bars` and `/live` subscribe) plus a plan change made by editing the plans file alone.
