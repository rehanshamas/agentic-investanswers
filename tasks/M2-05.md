# M2-05 Chart app: React + KLineChart, first ~500 bars, live bar, symbol and timeframe switch

GitHub issue: #22
Lane: B      Depends on: M2-03, M2-04      Owner inputs: none

## Goal
A browser chart (React + KLineChart, built-in indicators off, no TradingView libraries) that loads the newest ~500 bars of an instrument and timeframe from the History API, keeps the newest bar live over the live gateway, and lets the user switch instrument and timeframe.

## Plan

**What exists.** `GET /bars` (newest page, `next` cursor, display units) and `GET /live` (one WebSocket per browser, `?token=`, subscribe/unsubscribe, `bars` / `resync` / `error`) on the platform. The wire types live in `@aia/serving`, which depends on `@aia/data`. The `runtime:browser` rule (`notDependOnLibsWithTags`) follows dependencies transitively, so the browser cannot import serving, not even for types. `apps/web-chart` is an empty shell whose comment still says "Lightweight Charts" (a TradingView library, ruled out). The instrument listing exists only behind MCP (`ReadQueries.instruments`). There is no REST route for it.

**Facts checked in KLineChart 10.1.0 (Apache-2.0).** v10 has no `applyNewData`/`updateData`. Data comes through `setDataLoader({ getBars, subscribeBar, unsubscribeBar })` with `setSymbol` / `setPeriod`, times in milliseconds. A live bar is applied only if its time is greater than or equal to the newest bar's. **An older one is silently dropped.** Our protocol revises the previous bar every minute on 1m (the stored minute replaces its forming one) and within 2 s after a minute ends, so the chart needs our own handling for that (step 3).

**Steps**

1. **Client contract package `@aia/client-contract`** (`contexts/client-contract`, tags `type:context`, `layer:product`, depends only on the kernel, pure TypeScript, browser-safe). It holds what the platform promises the browser:
   - `DisplayBar`, `HistoryResponse`, `HistoryErrorCode`, the error body `{ error: { code, message, upgradeUrl? } }`, `HISTORY_DEFAULT_LIMIT`, `HISTORY_MAX_LIMIT`
   - the live protocol (`LiveClientMessage`, `LiveServerMessage`, `LiveWireUpdate`, `LiveErrorCode`, `parseClientMessage`, `LIVE_MAX_CLIENT_MESSAGE`)
   - `InstrumentListing` for step 2

   `@aia/serving` and `apps/platform` import and re-export these from it, so there is one source of truth. No byte on the wire changes and `eslint.config.mjs` is not touched. A test asserts the browser app's dependency graph never reaches `layer:data*` (the lint rule already enforces this; the test pins it).
2. **`GET /instruments`** on the platform (additive): every instrument with its timeframes served, which ones the caller's plan includes, and display precision (price and volume decimals). It reuses `ReadQueries.instruments` (same principal, rate limit and plan rules as `/bars`). It feeds the instrument picker and KLineChart's `pricePrecision` / `volumePrecision`, so the chart hard-codes no instrument.
3. **Framework-free data client** (`apps/web-chart/src/data/`, unit-tested in Vitest with a fake WebSocket and fake fetch, no browser):
   - `LiveConnection`: one WebSocket per tab, multiplexing ref-counted subscriptions. It resubscribes after a reconnect, with backoff (0.5 s doubling to 30 s, with jitter). It reconnects after a 1013 (too slow) close or a dropped socket, and a reconnect counts as a resync for every series. Errors are routed to their series.
   - `BarSeries` (one instrument and timeframe): it follows the contract (subscribe, then `GET /bars?limit=500`, then apply buffered and later updates by bar time). It reloads the newest page on `resync`. It keeps the bars it shows. A newer update appends, the same time replaces, and an older time replaces in place and is reported as a revision.
   - `KLineChart` adapter: a `DataLoader` over `BarSeries` (seconds to milliseconds, timeframe to `Period`). For a revision the chart would drop, it **patches the bar in KLineChart's own list and redraws**, if 10.1.0's `getDataList()` hands back the live list (to be checked in a spike first; a test pins the behaviour to the pinned version). Otherwise it falls back to `resetData()` served from `BarSeries` (no network), keeping the visible range. Backward loading answers "no more" for now: scroll-back is M2-06.
   - Auth: a bearer token, if one is stored, on REST (`Authorization`) and on `/live` (`?token=`). There is no sign-in screen in M2-05 (question 4). Locally, `AIA_DEV_AUTH=1`.
4. **React UI** (`apps/web-chart/src/ui/`), binding only: an instrument picker from `/instruments` (locked entries shown but disabled), a timeframe switcher (1m, 5m, 15m, 1h, 4h, 1D, 1W, 1M, limited to what is served), the chart, and a small status line (live, reconnecting, error messages from the server). KLineChart's built-in indicators stay off, with an overlay hook left for indicators drawn from server output (M3-02 part 2, M3-05). Switching unsubscribes the old series and subscribes the new one on the same socket.
5. **Vite** dev server and build for `apps/web-chart`, proxying `/bars`, `/instruments`, `/live` and `/auth` to the platform on :8080 (same origin, no CORS). Scripts: `pnpm chart` (dev) and a `build` target.
6. **Deterministic e2e** (the done-check):
   - `apps/platform/src/e2e-server.ts` runs the real `buildServer` over `MemoryDataLayer` seeded with fixed bars, plus `SimulatedLiveFeed` driven by a test-only control route, with dev auth and no Redis, S3, DynamoDB or Coinbase.
   - Playwright (Chromium) starts it and the built chart. It checks that the chart renders about 500 bars, then that it shows the newest bar's close. Driving a forming update and a stored minute, the newest bar's close changes on screen, and a revision of the previous bar is shown. It switches instrument and timeframe and gets fresh bars.
   - Assertions read the chart through a test hook (`window.__aiaChart` exposing KLineChart's data list), not pixels.
   - `pnpm e2e` locally, plus a CI job (installs Chromium).
   - A manual smoke run against the real `pnpm platform` plus `pnpm live` is listed in the PR for Sham.
7. **Docs:** a short "Chart app" note in `docs/architecture.md` (contract package, data client, previous-bar handling). Fix the web-chart comment.
