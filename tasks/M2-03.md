# M2-03 History API: `GET /bars?instrument&tf&before&limit` (paged, capped), cache first, then S3

GitHub issue: #20
Lane: A      Depends on: M2-02      Owner inputs: none

## Goal
Serve an instrument's bars for one timeframe over HTTP, newest page first and older pages on request, from the recent-bars cache when it can answer and from the stores otherwise, with a hard cap on bars per request.

## Plan

**What exists.** `apps/platform` is an empty composition root with no HTTP server yet. `contexts/access` is empty. `RecentBars.read(instrument, tf, { limit, before?, now })` from M2-02 already reads cache first, then the stores. The 1m reader (`RawMinuteSource`) and the feed-plan loader live in `apps/hydration`, and apps may not import each other.

**Steps**

1. **Make the 1m reader reachable from the platform.** Move `RawMinuteSource`, `ProviderOf`, `loadFeedPlan` and the two `ProviderOf` builders from `apps/hydration/src` into `@aia/hydration` (hydration owns raw, so reading it belongs there), and export them. `apps/hydration` then imports them from there; no behaviour change. This adds exports to hydration's entry but changes no existing contract.
2. **Paging in `RecentBars`** (market-data). Today a store read covers `limit` timeframe lengths, which can return fewer bars across weekends, holidays or missing history. `read` will widen the lookback (doubling, bounded) until it has `limit` bars or reaches the instrument's **earliest history**, passed in by the app from the feed plan's `defaultFrom`. The result says whether older bars may exist.
3. **The route, framework-free** (`contexts/market-data/src/adapters/http/history-route.ts`): `historyRequest(query, principal, now)` returns `{ status, body }`. It parses and validates the query, checks access (step 4), calls `RecentBars`, and shapes the response. Contract tests run against this directly.
   - Request: `GET /bars?instrument=BTCUSD&tf=5m&limit=500&before=1762800000`. `instrument` and `tf` are required. `limit` defaults to 500. `before` is optional, exclusive, and in UTC seconds.
   - **Cap:** at most **1,000 bars per request**. A larger `limit` is a `400` with code `limit_too_large` that states the cap, not a silent clamp.
   - Response `200`: `{ instrument, timeframe, bars: [{ time, open, high, low, close, volume }], next }`. Prices and volumes are numbers in real units, formatted from our scaled integers at the instrument's precision. `time` is the bar's open time in UTC seconds. `next` is the `before` value for the next older page, or `null` once history is exhausted.
   - Errors (`{ error: { code, message } }`): `400` bad or missing parameter, `400` `limit_too_large`, `401` no principal, `403` not allowed, `404` unknown instrument, `409` `timeframe_not_served` for 1D/1W/1M (until M1-08) and for stocks (not cooked until M1-08; their raw 1m is at Massive's precision).
4. **Principal and access seam** (`contexts/access`): `Principal` (`human` or `agent`, with an id) and an `AccessPolicyPort.canReadBars(principal, instrument, timeframe)`. Every request carries a principal (rule 4). Real sign-in is M2-08 and plans are M2-09, both waiting on OI-21. **Question 2** is what stands in until then.
5. **Server** (`apps/platform`): wires the S3 cooked store, the raw 1m reader, the Redis cache and `RecentBars`, then mounts `GET /bars` and `GET /health`. Adds `pnpm platform`, which listens on `AIA_PORT`, default 8080. JSON with gzip. No business rules in the app.
6. **Tests.**
   - Contract tests on the route: every parameter rule; the cap (1,000 accepted, 1,001 refused); response shape and units; paging (walking `next` from the newest page to the end gives every bar once, in order, with no gaps or overlaps); stock and 1D refused; 401 and 403.
   - Paging tests in `RecentBars` across a gap longer than one lookback.
   - One end-to-end test in `apps/platform` against the real server, on in-memory stores.
   - A local smoke run against MinIO and Redis with `curl`.

**Decisions (Sham, 2026-11-11)**
1. **Fastify** (new dependency, approved). Rust was discussed and set aside: the time goes to Redis and S3, not to the framework, and a second language would duplicate the business rules. Revisit only if M2-04's load test or M4-05 shows a real hot spot.
2. **Dev principal, local only:** with `AIA_DEV_AUTH=1`, requests count as a local human principal with full access; otherwise every request gets 401. M2-08 replaces the resolver.
3. **Cap 1,000 bars per request, default 500.**
4. **Move the 1m reader and the feed-plan loader into `@aia/hydration`:** approved.

**Out of scope:** WebSocket live updates (M2-04), real sign-in and plans (M2-08, M2-09), rate limits and safeguards (M2-10), deploying to AWS (M2-01).
