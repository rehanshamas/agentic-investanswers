## Plan (as built)
The loader lives in `market-data` as an adapter: this context owns bars, and the loader touches the file system. **No new package**, because `pnpm-workspace.yaml` covers only `apps/*`, `contexts/*` and `shared-kernel`, and adding a fourth would be an architecture change needing approval for no real gain. M1-03 imports it through `@aia/market-data`.

Two measurements drove the design, both taken before writing any code, and both of which would have made the loader throw on its first run:

1. **Volume carries up to 15 decimal places** in `btcusd_5m.csv` and `btcusd_15m.csv`, where the instrument's real precision is 8. Exactly **one row per file** is affected and the excess is 1e-15 to 4.55e-13 — float noise in TradingView's own summation. `parseScaled` refuses to round away precision, by design, so the loader retries at the rounded value only after proving the discarded part is below 1e-9. Anything larger is an error naming the scale to fix.
2. **ETH prices reach 3 decimal places**, not 2: two rows of 3,822 in `ethusd_1d.csv`, on 2020-05-28 and 2020-05-29 (`220.675`, `217.535`). Those are clean half-cent values, not artifacts, so `ETHUSD.priceScale` is **3**. BTC stays at 2.

### Surprises
1. **CI failed on the first push of #63, through my own oversight.** Four tests read the real exports, which are gitignored, so CI has no copy. This is exactly what #59 documented — parity is local-only until M1-13 — and I had not applied it to the test design. They now skip with a printed reason, so a skip is never silent.
2. **Volume carries up to 15 decimal places**, against a real precision of 8. One row per file, excess 1e-15 to 4.55e-13: float noise in TradingView's own summation. The loader rounds it only after proving the discarded part is under 1e-9. **That threshold is my judgement call** — about 2,000x the worst noise seen, 1e7 times smaller than one unit at scale 8.
3. **ETH prices reach 3 decimal places.** Two rows of 3,822 in `ethusd_1d.csv`, 2020-05-28 and 2020-05-29, values like `220.675` and `217.535`. Clean half-cents rather than artifacts, so `ETHUSD.priceScale` is **3** while BTC stays 2. **Worth a human opinion**: if those two bars are a TradingView quirk, the alternative is scale 2 with an explicit exception.
4. **Every row count quoted before this task was one too low.** `wc -l` counts newlines and these files have no trailing newline. My first verification script flagged all 16 of Sham's files as "PROBLEM" purely from that arithmetic — the files were always fine.
5. **The fixtures hook fired on four of my own commands**, including an issue body and a `git checkout` that merely mentioned the directory alongside a redirect. Working as intended, and the reason the explanatory notes live in `docs/bar-rules.md` rather than inside the protected directory.
