## Goal
Fetch 1-minute bars for BTCUSD and ETHUSD (CoinAPI `COINBASE_SPOT_BTC_USD`, `COINBASE_SPOT_ETH_USD`) from CoinAPI's REST history into the write-once raw store, one UTC day per file, so that a re-run, or a run resumed after a crash, writes nothing twice.

## Plan
**Use case: `application/backfill.ts`, `Backfill.run(instrument, from, until, now)`.**
1. Plan the UTC days from `from` to the last *complete* day. A day counts as complete once it ended at least `settle` ago (default 1h, so CoinAPI has finished the day). `now` is an argument, so there is no clock read in domain or application code.
2. For each day: if `hasDay`, skip it (this is what makes the run resumable and idempotent). Otherwise fetch the whole day, check it with `assertStorableRawDay`, and `putDay` it once. Losing the race with another writer (`RawDayAlreadyStoredError`) counts as a skip, not an error.
3. **Never store a partial or empty day.** Raw is write-once, so a partial day could never be completed later. The day is fetched whole into memory and written in one put, so a crash loses at most the day in flight. A day the provider returns empty is reported and not stored, so a later run can retry it.
4. It returns and logs counts: days planned, stored, skipped (already there), empty, and bars written.

**Port: `application/history-provider-port.ts`**, `fetchDay(instrument, date): Promise<Bar[]>`, so the use case is tested with a fake provider and makes no HTTP calls.

**Adapter: `adapters/coinapi/`**
- `coinapi-history.ts`: makes the call `GET https://rest.coinapi.io/v1/ohlcv/{symbol_id}/history?period_id=1MIN&time_start=<day>&time_end=<next day>&limit=1500` with header `X-CoinAPI-Key`, using Node's own `fetch` (no new dependency). It retries 429 and 5xx with exponential backoff, honouring `Retry-After`. Error messages never include the key. Requests run one at a time.
- `coinapi-ohlcv.ts`: parses the response JSON into Bars. Stamp = `time_period_start` (the minute's open, UTC). Prices are scaled at the instrument's `priceScale` and volume at `volumeScale`, with the same rule as the M1-02 loader: digits beyond the scale are accepted only when they are provable float noise (≤ 1e-9); anything larger throws rather than being rounded into raw. Bars outside the requested day, duplicates and incoherent bars throw.
- Provider symbols: `BTCUSD` → `COINBASE_SPOT_BTC_USD` and `ETHUSD` → `COINBASE_SPOT_ETH_USD`, matching docs/bar-rules.md.

**CLI: `apps/hydration/src/backfill.ts`**, run as `pnpm backfill [--symbol BTCUSD] [--from 2024-11-01] [--until YYYY-MM-DD]`.
- It wires `S3RawBarStore` (MinIO), `CoinApiHistory` and the market-data parity instruments (for their scales).
- It reads `COINAPI_KEY` from the environment through `tsx --env-file=.env`, and refuses to start without it.
- It prints progress per month and a final summary. Exit codes: 0 done, 1 some days failed, 2 setup error.

**Tests**
- The parser, on a synthetic response in CoinAPI's shape (not real CoinAPI data): scaling, float noise, real excess precision refused, a bar outside the day refused, duplicates refused.
- The HTTP client, with a fake `fetch`: the URL, the header, retry on 429, and the key absent from errors.
- `Backfill`, with a fake provider and an in-memory raw store: skips existing days; resumes after a crash on day N; a second run writes nothing; empty days are not stored; the last complete day respects `settle`; a lost race counts as a skip.
- MinIO integration through the existing skip-if-unreachable pattern.

**Done-check run (real calls, local MinIO):** `pnpm backfill --from 2024-11-01` for both symbols, about 740 days each, then a second run that must report 0 stored. Then `pnpm parity --timeframe 1m` as a first real look (not part of this task's done-check).

**Change after approval (Sham, 2026-11-09): history comes from Coinbase, not CoinAPI.** Sham is on CoinAPI's free plan, a one-time $25 credit charged per 100 bars. A 2-year BTC+ETH backfill is about 22,000 credits, above that. And this machine cannot reach `rest.coinapi.io` at all (TLS reset, while `www.coinapi.io` works). Coinbase Exchange's public candles API (`api.exchange.coinbase.com/products/{BTC-USD|ETH-USD}/candles?granularity=60`) is free, needs no key, and is the venue the exports use. On 6 minutes of 2026-11-07 it matched `btcusd_1m.csv` exactly on OHLCV. So:
- The adapter is `adapters/coinbase/coinbase-candles.ts`. It reads 300 candles per request (the API maximum; `start` and `end` are both inclusive), so 5 requests per UTC day. Rows are `[time, low, high, open, close, volume]`, newest first. It paces itself under the public limit and retries 429, 5xx and network errors. There is no key.
- Raw is stored under provider `coinbase`, and the parity CLI's 1m source is pointed there.
- CoinAPI remains the plan for the live stream (M1-05). Data-licence terms for Coinbase are part of OI-22.

**Out of scope:** the live stream (M1-05), gap repair (M1-09), stocks (M1-07), cooking (M1-06 exists; triggering it after a backfill is not this task).
