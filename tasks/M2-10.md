## Plan
Standing approval from Sham (2026-11-13); plan posted in the project thread. No new dependency: `redis` is already used by market-data and indicators, now also by access.

1. Domain: rate buckets (human reads, agent reads, sign-in, sign-up, agent key changes), rules as configuration, fixed windows.
2. `RateLimiter` over a `RateCounterPort`; a failed counter lets the request through and reports it.
3. Counters: memory and Redis (INCR plus EXPIRE in one script), with a shared contract test. `config/safeguards.json` loaded at start-up.
4. Platform: 429 `rate_limited` with `Retry-After` on `/bars`, `/plan`, `/live` (the upgrade), sign-in, sign-up, agent key create and revoke.
5. The bars-per-request cap already exists (`HISTORY_MAX_LIMIT`, 1,000; M2-03). WAF rules go into the AWS stack (M2-01), recorded as T-06.
