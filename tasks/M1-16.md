# M1-16 Data layer boundary: one data-access interface for the rest of the app

GitHub issue: #82
Lane: A      Depends on: M1-15 (done)      Owner inputs: none

## Goal
Make one data-access interface the only way the rest of the app gets bars (history, ranges, live updates), so that no other module touches storage, the cache or provider code. Running the data layer as its own service later then means writing one new adapter behind that interface.

## Plan

**What exists**
- Only the platform reads bars today, but it builds the data layer itself from raw parts. `apps/platform/src/main.ts` imports `@aia/hydration` (the raw store, the feed plan, the 1m reader) and `@aia/market-data`'s storage and cache adapters (`S3CookedBarStore`, `RedisRecentBarsCache`, `RedisLiveBarsBus`, `CookedReader`, `RecentBars`), and wires them together.
- No other context reads bars yet. The indicator engine (M3-04), backtests and the agent API (M4) soon will. Putting the boundary in now means they start on the interface.
- Lint rules today separate only apps, contexts and the kernel, so nothing stops any module importing storage code.

**Steps**
1. **A new package, `@aia/data` (`contexts/data`): the data layer's one front door.**
   - `DataAccess`, the interface, in our types only:
     - `instruments`
     - `history`: the History API rules, the same `parse`/`run` as now
     - `bars(symbol, tf, from, until)`: scaled bars, settled plus tail, for the indicator engine and backtests
     - `recent(instrument, tf, { limit, now })`
     - `subscribe(listener)`: live bar updates
     - `close()`
   - Two adapters behind it:
     - `openLocalDataLayer(env)`: everything `main.ts` wires today (S3, the feed plan, Redis), moved here unchanged.
     - `memoryDataLayer(...)`: for tests and the gateway load test.
   - It also re-exports what serving code needs to speak the data layer's language: `HistoryQuery`'s result types, the live protocol, and `LiveGateway`, which fans updates out to browsers.
2. **Platform wiring:** `main.ts` becomes `const data = await openLocalDataLayer(env)`. The server uses `data.history`; the gateway subscribes through `data.subscribe`. The platform imports only `@aia/data` (plus `@aia/access`), never `@aia/hydration` or `@aia/market-data`. The gateway load test uses `memoryDataLayer`.
3. **The boundary, enforced by lint** (stricter only):
   - Nx tags: `layer:data-internal` on `hydration` and `market-data`; `layer:data` on `data`; `layer:data-app` on `apps/hydration` (the data layer's own process).
   - Everything else (platform, web-chart, access, indicators, backtesting, agent, audit, preferences) gets `layer:product`, with the rule: never depend on `layer:data-internal`.
   - The browser app (`web-chart`) also may not depend on `@aia/data`, which would put server and storage code in the browser bundle.
   - Proved by linting a deliberately bad import from the platform and from a product context, and seeing it fail. A test runs ESLint on throwaway files, so it stays proved in CI.
4. **Contract tests:** one suite that any `DataAccess` adapter must pass. It runs today against the in-process adapter on in-memory stores; a future remote adapter must pass the same suite. It covers:
   - instruments
   - history (shape, errors, paging)
   - `bars` equals a roll-up of raw minutes across the watermark
   - `recent`
   - live updates reaching a subscriber in order
5. **Docs:**
   - `docs/architecture.md` gets "Data layer boundary": the rule, the interface, and the design note for a separate service. That note covers a remote adapter over HTTP for queries and the existing Redis bus for live updates; service-to-service auth; the same contract tests; and that gRPC stays deferred.
   - `docs/decisions-record.md` T-05 gets "in code since M1-16".
   - An `AGENTS.md` for `contexts/data`.

**Decisions (Sham, 2026-11-14)**
1. **A new package, `@aia/data`.**
2. **"Do what's best, no temporary or band-aid solutions."** So the serving code moves out of market-data rather than being re-exported. A new context, **`@aia/serving`**, takes what the platform promises its clients:
   - the History API rules (parameters, the cap, display units)
   - `LiveGateway` and its wire protocol
   - `displayBar`

   They are about serving clients, not about data. `@aia/data` then speaks bars in our scaled units only: instruments, what is served, history pages, ranges, newest bars, live updates. Market-data keeps bars, cooking, the cache and the bus. The gateway load test's simulated feed (built on `FormingBars`) becomes a simulator adapter in `@aia/data`, so the platform never reaches data internals, even in tests.
3. **The lint rule as best:** product modules never depend on data internals, and the browser app never depends on `@aia/data` or `@aia/serving`'s server code.

Tests move with their code, with imports changed and no assertions changed.

**Size:** about a day and a half, with the serving move.

- **Boundary test (10):**
  - refused: platform, indicators, serving and backtesting importing hydration or market-data; the browser app importing `@aia/data` or `@aia/serving`
  - allowed: the front door, and `apps/hydration` using the internals

- **Moved tests pass:** serving 38, platform 56 (sign-in, plans, `/live`, `/bars`, the CI load test).
- **One assertion changed (Sham to confirm):** `HistoryQuery`'s test expected `earliest` in the page query. Where history starts is now the data layer's to apply, so `HistoryQuery` no longer passes it. The DataAccess contract covers it.
