## Plan

### Three questions that need your answer before I write code

**1. New dependencies — this is the CLAUDE.md "stop and ask" trigger.** The task cannot be done without them, and `dependencies` is currently empty everywhere.

- `@aws-sdk/client-s3` — the S3 adapter, pointed at MinIO locally with `forcePathStyle`. Uncontroversial: `docs/architecture.md` already names S3 and MinIO.
- **A Parquet library, and here there is a real snag.** The architecture says Parquet **zstd**. The usual pure-JS option, `@dsnp/parquetjs`, supports gzip, snappy, brotli and lz4 — **but not zstd**. Getting zstd means a WASM library (`parquet-wasm`, built on Rust arrow), which is heavier and adds a WASM load step. So pick one:
  - **(a) `@dsnp/parquetjs` with snappy, and amend the architecture note.** Pure JS, simplest, widely used. Snappy is faster to read and write than zstd; zstd's advantage is roughly 20–30% smaller files. My recommendation — storage cost is not an MVP constraint, and this is reversible because raw is write-once but re-readable, so a later re-encode is a batch job, not a migration.
  - **(b) `parquet-wasm` for genuine zstd.** Matches the architecture exactly, at the cost of a WASM dependency in both processes.
  - **(c) Something else you have in mind.**

**2. One port or two?** The backlog row says "behind `BarStorePort`", singular, but raw and cooked are not the same thing: raw is write-once, keyed by provider/instrument/day, and `contexts/hydration` owns it; cooked is rewritable, keyed by instrument/timeframe, and `contexts/market-data` owns it (per each context's `AGENTS.md`). I propose **two ports**, each in its own context's `application/` layer, each with its own S3 adapter:

```
contexts/hydration/src/application/raw-bar-store-port.ts     RawBarStorePort
contexts/hydration/src/adapters/s3-raw-bar-store.ts
contexts/market-data/src/application/cooked-bar-store-port.ts  CookedBarStorePort
contexts/market-data/src/adapters/s3-cooked-bar-store.ts
```

The cost is that about 30 lines of S3 client setup and Parquet encoding exist twice, because the boundary rules forbid sharing it: `shared-kernel` must stay pure (no AWS SDK), and a context may only import another through its `index.ts`. I think duplicating 30 lines is the right price for a clean boundary, and it is what CLAUDE.md rule 1 implies. The alternative is one shared port in `market-data` that `hydration` imports — fewer lines, but then the context that explicitly does not own cooked bars defines the raw contract too. **Say if you would rather have one port.**

**3. Partitioning for cooked bars.** Raw is fixed by the backlog row: one file per provider, instrument and day. Cooked has no stated layout. I propose one file per instrument, timeframe and **month** for intraday timeframes, and per **year** for 1D/1W/1M — which keeps files in the 1k–50k row range rather than 60-row files for 1W. Flagging it because M1-06's incremental update and M2-03's paging both inherit this choice.

### A trap worth naming now
**Storage paths must use the lower-case timeframe tokens**, the same ones `docs/bar-rules.md` defines for export file names: `1m`, `5m`, `15m`, `1h`, `4h`, `1d`, `1w`, `1mo`. On real S3 keys are case-sensitive, so `1m` and `1M` would be distinct and fine — but **MinIO stores objects as files**, and on macOS APFS the two fold together, so `.../1M/2024-03.parquet` would silently overwrite `.../1m/2024-03.parquet` on your machine and not on staging. That is the worst class of bug: passes in CI, corrupts locally, or the reverse. One mapping function, used by both stores.

### Write-once enforcement
`PutObject` with `IfNoneMatch: '*'` makes the write atomically conditional, so a second write fails at the store rather than relying on a read-then-write check that two processes could interleave. S3 has supported this since late 2024; **MinIO's support needs verifying**, which I will do against the local container as the first step after the dependency is approved. Fallback if MinIO lacks it: `HeadObject` then `PutObject`, with the race documented and acceptable because hydration is a single writer per instrument. The test for "writing a raw file twice is rejected" covers the port's behaviour either way.

### Shape of the work
1. Verify MinIO's conditional-write support (throwaway script, no commit).
2. `RawBarStorePort`: `putDay(provider, instrument, date, bars)`, `getDay(...)`, `hasDay(...)`. Rejects a second write. Rejects bars that do not all fall on the stated day.
3. `CookedBarStorePort`: `put(instrument, timeframe, bars)`, `getRange(instrument, timeframe, from, to)`, reading across partition boundaries.
4. Parquet encoding: columns for time, open, high, low, close, volume, stored as the scaled integers M0-04 defines so a round trip is exact and no float appears anywhere on disk.
5. Tests: round trip for both stores; second raw write rejected; a range read spanning two partitions; the timeframe-token mapping; bars rejected when they do not match the partition they are being written to.

**Surprises worth knowing.**
1. **parquetjs silently ignores the writer-level `compression` option.** My first spike files all claimed a codec and were all uncompressed, 684 bytes each, no warning. Compression only works declared **per column**. There is now a test asserting the codec id recorded inside written files, because the library will never tell you.
2. **Its types promise codecs it cannot do** — `ParquetCompression` includes ZSTD, LZO and LZ4, but the runtime table has only UNCOMPRESSED, GZIP, SNAPPY, BROTLI. Asking for ZSTD typechecks and throws at runtime. Hence the local `SupportedCompression` type listing only the four that were verified.
3. **MinIO does honour `IfNoneMatch: '*'`** (412 PreconditionFailed), so write-once is atomic rather than read-then-write. Better than the fallback in the plan.
4. **The duplication is ~200 lines, not the ~30 I estimated** in the plan: the Parquet codec and the S3 wrapper both exist twice. Still the only option that keeps boundaries intact without a new package, and both copies carry a `DELIBERATE DUPLICATE` header. A third consumer is the signal to add a shared adapters package.
5. **One cast was unavoidable**: parquetjs types its sink as `Pick<fs.WriteStream, 'write' | 'end'>`, so a `stream.Writable` fails to typecheck purely over `end()`'s return type, though at runtime only those two methods are called. Documented where it sits.
