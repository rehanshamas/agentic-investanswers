## Plan
Standing approval from Sham (2026-11-13). New dependency `@aws-sdk/client-dynamodb` approved by Sham the same day ("use what's in permanent plans", DynamoDB).

1. `contexts/access` domain: accounts (email normalised, password rules), sessions (30 days, bearer token parsing).
2. Application: ports for accounts, sessions, password hashing and tokens; `SignIn` (sign-up, sign-in, sign-out, current account) which is also the `PrincipalResolverPort`.
3. Adapters: scrypt and node:crypto tokens (no extra dependency); memory stores; DynamoDB stores (one table, conditional transaction for unique emails, session TTL), `ensureUsersTable` for local runs.
4. Platform: `/auth/*` routes; `accessFromEnv` uses sign-in unless `AIA_DEV_AUTH=1`; `pnpm platform` wires DynamoDB.
5. CI gets a DynamoDB Local service so the store tests run there.

## Handoff
**Done.** Sign-in in `contexts/access`, routes in the platform, DynamoDB stores. Tests: 28 in `@aia/access` (memory always; DynamoDB contract tests skip without DynamoDB Local, run in CI), 7 auth route tests in the platform including `/live?token=`. `pnpm check` green.

**Surprises.**
- The platform's error handler turned Fastify's own 4xx refusals (unreadable JSON, oversized body) into 500s; it now keeps their status.
- DynamoDB Local could not be fetched in this cloud session (download blocked), so the DynamoDB adapter is exercised only in CI. Run `docker compose up -d && pnpm --filter @aia/access test` locally to see it.
